AI Provider Configuration Persistence - Final Verification

🐛 Original Bug

Issue: AI Provider configurations were being lost when users navigated between tabs or refreshed the page.

Root Cause: The getUserAIProviders() function was overwriting localStorage with empty arrays when API responses were empty, even if user configurations existed.

User Impact: Users would configure AI providers (enter API keys, select models), but when they navigated to Materials tab or refreshed, their configurations would disappear.

✅ Fix Applied

Solution: Modified getUserAIProviders() to treat localStorage as the authoritative source for user configurations.

Key Changes:

  • Always check localStorage first and return existing configs if found
  • Only fetch from API for initial setup when no local configs exist
  • Never overwrite localStorage with empty API responses
  • Removed automatic overwriting with DEFAULT_AI_PROVIDERS
